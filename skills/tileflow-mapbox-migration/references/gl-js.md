# GL JS migration decisions

- **Mapbox GL JS.** Inspect `mapbox://` styles, tiles, sprites, glyphs, Standard imports, slots, and basemap feature IDs. Rebuild the required cartography with released Tileflow maps and semantic modules. Match application layers to a documented placement and inspect the compiled result. A Studio URL or slot name cannot select the corresponding Tileflow layer. [Mapbox sources and layers](https://docs.mapbox.com/mapbox-gl-js/guides/styles/work-with-layers/)
- **MapLibre GL JS.** Compare the installed renderer with the MapLibre range in the release manifest or the published Tileflow adapters' `peerDependencies`. Keep the renderer if its version is supported. If reaching the supported range requires a major upgrade, confirm that change before migrating. Keep compatible app-owned GeoJSON and map listeners. Serve the compiled Tileflow manifest with the build integration and follow the direct MapLibre guide for worker, CSS, fonts, protocols, request handling, and disposal. Resolve the named map before constructing it. Style replacement can remove runtime layers and feature state. Reapply them once and detach the same listeners on teardown. [MapLibre Map API](https://maplibre.org/maplibre-gl-js/docs/API/classes/Map/)
- **MapTiler SDK JS.** Inventory MapTiler style presets, Cloud URLs, API client helpers, and plugins separately. Replace a preset with a selected Tileflow design. Keep a provider key only for calls that still go to that provider. Check the real routing or matrix client in the app before mapping it to Tileflow. [MapTiler SDK](https://docs.maptiler.com/sdk-js/api/) · [MapTiler API client](https://docs.maptiler.com/sdk-js/api/api-client/)
- **Markers and events.** A direct MapLibre map can retain native markers, popups, and map events. A framework map can use Tileflow annotations and interaction bindings from the installed release. Keep marker IDs, keyboard activation, and popup content working. Match a layer event to an application-owned source and layer.
- **Services.** Mapbox documents that Geocoding API responses may only be used with a Mapbox map. Migrate Geocoding with the basemap or leave the screen on Mapbox. Review the applicable terms and the Tileflow service guides. Adapt geocoder results, route geometry, and source-by-target matrices at the caller. Preserve unreachable cells and returned attribution. Check travel modes, traffic, retention, and origin restrictions before removing the old service. Static image creation belongs on a trusted server. The client displays the returned image. Local preview and capture need no provider token for public Tileflow resources. [Mapbox Geocoding API](https://docs.mapbox.com/api/search/geocoding/)
- **Routing cutover.** Check hosted network and engine availability separately from the published client. If activation is pending or the service returns `ROUTING_UNAVAILABLE`, review the current Directions or Matrix provider's terms and ask the user before using its results beside the new map. Apply the same check to other retained providers. Keep the screen on its existing map until that decision is settled. Qualify the new adapter with fixtures and report hosted verification as pending.
